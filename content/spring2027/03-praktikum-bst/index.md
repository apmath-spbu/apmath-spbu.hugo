Практикум блока деревьев: собираем класс BST целиком — от владения узлами до стресс-теста. Главное новое — **удаление** (на семинарах его откладывали) и итеративный in-order, обещанный на занятии 1. Всё написанное сегодня — каркас первого домашнего задания семестра. Замеры реальные (Apple M-серия, `clang++ -O2`).

Два правила курса в силе: **инвариант прежде кода** (для каждой операции проговариваем, что она сохраняет) и **эталон прежде веры** (правильность подтверждает сверка со `std::set` на случайных операциях, а не взгляд — методика занятия 16).

## Каркас: владение и правило пяти

```cpp
class BST {
    struct Node { int key; Node *l = nullptr, *r = nullptr; };
    Node*  root_ = nullptr;
    size_t size_ = 0;
public:
    BST() = default;
    ~BST() { clear(root_); }
    BST(const BST&)            = delete;   // копию запрещаем честно
    BST& operator=(const BST&) = delete;
    BST(BST&& o) : root_(o.root_), size_(o.size_) { o.root_ = nullptr; o.size_ = 0; }
    BST& operator=(BST&& o) {
        if (this != &o) { clear(root_); root_ = o.root_; size_ = o.size_;
                          o.root_ = nullptr; o.size_ = 0; }
        return *this;
    }
    // операции — ниже
};
```

Класс **владеет** узлами: создал в insert — обязан удалить в деструкторе (правило пяти, занятия 7 и 22). Копирование запрещено через `= delete`: глубокая копия — задача со звёздочкой, а молчаливая мелкая — двойное удаление. Move — три строки: украсть корень, обнулить донора. Сырые указатели внутри класса — законный стиль, пока владение не утекает наружу.

{{% expand title="А можно на unique_ptr?" %}}
Да: `std::unique_ptr<Node> l, r;` в узле и `std::unique_ptr<Node> root_`. Деструктор и запрет копирования появляются бесплатно, утечки исключены по построению. Цены две: во-первых, перецепки в erase выражаются через `std::move` и временные владельцы — код честнее, но шумнее; во-вторых, деструктор по умолчанию рекурсивен по цепочке unique_ptr — на вырожденном дереве он так же роняет стек, и итеративный clear всё равно приходится писать руками. Для учебного разбора механики выбран сырой вариант; в ДЗ разрешены оба.
{{% /expand %}}

**Деструктор — это post-order** (занятие 1: «безопасно удалить — сначала детей»):

```cpp
void clear(Node* t) {
    if (!t) return;
    clear(t->l);
    clear(t->r);
    delete t;
}
```

Коварство: глубина рекурсии равна высоте, и вырожденное дерево на $10^6$ узлов уронит стек **прямо в деструкторе** — там, где ошибку не ищут. Итеративный clear со своим стеком — задача ★★ домашнего задания. Чистоту проверяем как в занятии 11: санитайзер и `leaks`, ноль утечек после стресс-теста.

## Вставка: указатель на указатель

```cpp
void insert(int k) {
    Node** cur = &root_;                    // адрес ПОЛЯ, не узла
    while (*cur) {
        if (k == (*cur)->key) return;       // дубликат — молча выходим
        cur = (k < (*cur)->key) ? &(*cur)->l : &(*cur)->r;
    }
    *cur = new Node{k};                     // пишем прямо в поле
    ++size_;
}
```

`cur` указывает не на узел, а на **поле**, где лежит указатель: на `root_`, чей-то `l` или `r`. Дошли до пустого поля — записали в него новый узел: ни рекурсии, ни хранения родителя, ни разбора «я левый или правый ребёнок». Тот же приём унифицирует удаление — «перецепить поддерево» превратится в одно присваивание `*cur = ...`.

## Итеративный in-order: долг занятия 1

```cpp
template <class F>
void inorder(F visit) const {
    std::vector<Node*> st;                  // свой стек (зан. 8)
    Node* t = root_;
    while (t || !st.empty()) {
        while (t) { st.push_back(t); t = t->l; }   // влево до упора
        t = st.back(); st.pop_back();
        visit(t->key);                      // самый левый из оставшихся
        t = t->r;                           // один шаг вправо
    }
}
```

Свой стек хранит **недообработанных предков** — ровно то, что системный стек хранил в кадрах вызовов (занятие 5). Инвариант: вершина стека — ближайший предок, чьё левое поддерево ещё не допройдено. Памяти по-прежнему $O(h)$, но лимит теперь — вся куча, а не 8 МБ системного стека: цепочка из $10^6$ узлов больше не страшна. Лямбда-visitor (занятие 14) делает обход универсальным: печать, выгрузка в вектор, проверка порядка — один код.

## Удаление: три случая

**Случаи «лист» и «один ребёнок» — перецепить и забыть.** Ребёнок (или nullptr) занимает поле удаляемого — всё поддерево целиком, порядок не трогается. Благодаря `Node**` оба случая — одна строка, без разбора «кем я был родителю».

**Два ребёнка — пересадить successor.** Successor удаляемого узла — минимум правого поддерева: он больше всего левого поддерева (он правее корня) и меньше остального правого (он там минимум) — значит, имеет право стоять на месте удаляемого. И его самого легко удалить: у минимума нет левого ребёнка, это всегда случай «0 или 1 ребёнок».

```cpp
void erase(int k) {
    Node** cur = &root_;
    while (*cur && (*cur)->key != k)
        cur = (k < (*cur)->key) ? &(*cur)->l : &(*cur)->r;
    if (!*cur) return;                      // нет такого ключа
    Node* t = *cur;
    if      (!t->l) { *cur = t->r; delete t; }
    else if (!t->r) { *cur = t->l; delete t; }
    else {
        Node** s = &t->r;                   // минимум правого поддерева
        while ((*s)->l) s = &(*s)->l;
        t->key = (*s)->key;                 // пересадка ключа
        Node* dead = *s;
        *s = dead->r;                       // у минимума нет l
        delete dead;
    }
    --size_;
}
```

Стоимость: спуск до узла + спуск до минимума — суммарно $O(h)$. Симметричный вариант через predecessor (максимум левого поддерева) так же корректен.

> [!warning] Что пересадка ломает
> Адрес узла с пересаженным ключом изменился — внешние указатели и «итераторы» на него мертвы. Настоящий `std::set` поэтому перевешивает **узлы**, а не ключи: его итераторы переживают чужие erase. Цена — код удаления в разы длиннее нашего.

## Проверки

**Валидатор инварианта** — задача B прошлого семинара, теперь рабочий инструмент. Каждый узел проверяется против коридора $(lo, hi)$, а не против родителя; спуск влево сужает коридор сверху, вправо — снизу:

```cpp
bool isBST(Node* t, long long lo, long long hi) {
    if (!t) return true;
    if (t->key <= lo || t->key >= hi) return false;
    return isBST(t->l, lo, t->key) && isBST(t->r, t->key, hi);
}
bool valid() const { return isBST(root_, LLONG_MIN, LLONG_MAX); }
```

Границы — `long long`, чтобы ключи-крайности `INT_MIN`/`INT_MAX` не требовали костылей (семестр 1, занятие 3). Во время отладки erase зовите `valid()` после каждой пачки операций — дёшево и бесценно.

**Стресс-тест против std::set** — судья беспристрастный:

```cpp
BST mine;  std::set<int> ref;
std::mt19937 rng(42);
for (int step = 0; step < 100'000; ++step) {
    int k = int(rng() % 1000);              // тесный диапазон: коллизии неизбежны
    switch (rng() % 3) {
      case 0: mine.insert(k); ref.insert(k); break;
      case 1: assert(mine.find(k) == (ref.count(k) > 0)); break;
      case 2: mine.erase(k);  ref.erase(k);  break;
    }
}
assert(mine.size() == ref.size());
assert(mine.valid());
```

Ключи из тесного диапазона — нарочно: так erase постоянно попадает и в листья, и в узлы с двумя детьми. Seed фиксирован — упавший assert сразу даёт воспроизводимый сценарий.

**Секундомер** — тот же тест, только на $10^6$ операций:

```
# микс 10^6 операций (50% insert / 30% find / 20% erase), база 5·10^5
наш BST:    263 мс     найдено 50 451
std::set:   311 мс     найдено 50 451     # совпало
размер после: 853 678 у обоих             # совпало
```

На случайном миксе наш 24-байтовый узел обгоняет 40-байтовый узел set — меньше памяти, меньше кэш-промахов (занятие 17). Помним занятие 2: это выигрыш на удачном входе; отсортированная серия — и мы в $\Theta(n)$, а set невозмутим. Простая структура плюс эталонный тест — отличный рабочий инструмент, но в библиотеку идёт гарантия.

## Бонус: диапазонный запрос с отсечением

```cpp
long long rangeCount(Node* t, int lo, int hi) {
    if (!t) return 0;
    if (t->key < lo) return rangeCount(t->r, lo, hi);   // всё левое — мимо
    if (t->key > hi) return rangeCount(t->l, lo, hi);   // всё правое — мимо
    return 1 + rangeCount(t->l, lo, hi) + rangeCount(t->r, lo, hi);
}
```

```
# 10^6 ключей, диапазон из 1000 подряд идущих
rangeCount:     2.2 мкс/запрос
полный обход:  19 000 мкс                 # ×8600
```

Инвариант отсекает поддеревья целиком: посещаем $O(h + \text{ответ})$ узлов. Идея «спрашивай поддерево целиком, не заходя внутрь» вырастет в **дерево отрезков** в конце семестра (занятие 28).

## Задачи практикума

1. **k-й минимум.** Верните k-й по возрастанию ключ.

   {{% expand title="Разбор" %}}Итеративный in-order отдаёт ключи по порядку — остановитесь на k-м (visitor со счётчиком и ранним выходом, либо перепишите цикл). Стоимость O(h + k). Бонус ★: храните в каждом узле размер его поддерева — тогда спуск «если в левом поддереве ≥ k узлов, иди влево; иначе вычти и реши, не корень ли ответ» отвечает за O(h) без обхода. Поддержка размеров при insert/erase — плюс одна строка на каждом спуске.{{% /expand %}}

2. **LCA в BST.** Ближайший общий предок ключей a и b (оба есть в дереве).

   {{% expand title="Разбор" %}}Спуск от корня: пока a и b строго по одну сторону от текущего узла (оба меньше — влево, оба больше — вправо), спускайтесь; как только разошлись (или один равен узлу) — вы в ответе. Корректность из инварианта: узел, где пути расходятся, лежит между a и b, а любой узел выше — нет. O(h), в произвольном дереве без инварианта пришлось бы работать сильно больше.{{% /expand %}}

3. **Печать диапазона [l, r] по возрастанию за O(h + ответ).**

   {{% expand title="Разбор" %}}Скрестите итеративный in-order с отсечением: в фазе «влево до упора» не заходите в поддеревья с ключом < l (спускайтесь сразу вправо), при visit печатайте только ключи ≤ r и прерывайтесь, когда ключ превысил r. Рекурсивный вариант проще: как rangeCount, но с печатью между рекурсивными вызовами (in-order-порядок сохраняется). Проверьте края: пустой диапазон, диапазон из одного ключа, весь диапазон.{{% /expand %}}

## Домашнее задание блока деревьев (сдача через Git + HR)

1. **Класс BST**: insert / find / erase / min / max / successor + итеративный in-order с лямбдой-visitor. Ноль утечек по санитайзеру.
2. **Повторы**: режим multiset — счётчик в узле; erase уменьшает счётчик. Сравните с подходом «класть равные влево» и объясните, чем он хуже (подсказка: что происходит с формой дерева и с erase).
3. **Стресс-тест** против `std::multiset`: $10^5$ случайных операций из тесного диапазона; сверка ответов, размера и `valid()` на каждой тысяче шагов.
4. **rangeCount(l, r)** с отсечением + замер против полного обхода на $10^6$ ключей.
5. ★ **Перестройка**: `rebuild()` — выгрузить in-order в вектор и собрать идеально сбалансированное дерево рекурсией по середине; покажите высоту до и после на вырожденном входе.
6. ★★ **Итеративный clear** со своим стеком — деструктор, переживающий цепочку из $10^6$ узлов (проверьте именно на ней).

Критерии как всегда: история коммитов по шагам, замеры со своей машины, стресс-тест обязателен (без него — половина баллов). Задачи с автотестами — в контесте HR.
