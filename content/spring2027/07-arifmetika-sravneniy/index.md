Мы уже месяц живём по модулю: хеш Картера–Вегмана считался mod p (занятие 5), полиномиальный хеш — mod $2^{64}$ (занятие 6), ведро таблицы — `k % m`, кольцевой буфер — `(i + 1) % n` (семестр 1, занятие 8). Пора познакомиться с этой арифметикой всерьёз: впереди проверка простоты и факторизация (занятия 10–11) и криптография (13–15), где всё стоит на сегодняшних четырёх кирпичах — `norm`, `mulmod`, `powmod`, `extgcd`. Замеры реальные (Apple M-серия, `clang++ -O2`).

## Кольцо вычетов

> [!def] Сравнение по модулю
> $a \equiv b \pmod N$ означает: $N$ делит разность $a - b$. Целые числа распадаются на $N$ классов по остатку — часовой циферблат с $N$ делениями.

> [!theorem] Корректность помодульных вычислений
> $(a + b) \bmod N = ((a \bmod N) + (b \bmod N)) \bmod N$ — и так же для вычитания и умножения.
> {{% notice style="prove" expanded="true" %}}
Подставим $a = q_1 N + r_1$, $b = q_2 N + r_2$: $a + b = (q_1 + q_2)N + (r_1 + r_2)$, и слагаемое с $N$ исчезает под модулем; для произведения $ab = (\ldots)N + r_1 r_2$ — аналогично. Практический смысл: считая длинное выражение mod $N$, режьте модулем **каждый** промежуточный результат — числа никогда не вырастут больше $N^2$.
{{% /notice %}}

Пример с циферблата: сейчас 9 часов, что будет через 55 часов? $9 + 55 \equiv 9 + 7 \equiv 4 \pmod{12}$.

Чего **нельзя**: делить. $10 \equiv 4 \pmod 6$, но $5 \not\equiv 2 \pmod 6$. Деление вернём в конце занятия — через обратный элемент.

### Две ловушки C++

```cpp
// ЛОВУШКА 1: оператор % наследует знак делимого
(-7) % 3 == -1                       // не 2! (сем. 1, зан. 3)
long long norm(long long a, long long n) {
    return ((a % n) + n) % n;        // всегда в [0, n)
}

// ЛОВУШКА 2: (a * b) % n переполняется раньше, чем взят модуль
using u64 = uint64_t;
u64 mulmod(u64 a, u64 b, u64 n) {
    return u64(__uint128_t(a) * b % n);
}
u64 addmod(u64 a, u64 b, u64 n) {    // для n < 2^63
    a += b;
    return a >= n ? a - n : a;
}
```

Семантика `%` в C++ — деление «к нулю», остаток со знаком делимого; для математики нужен остаток в $[0, N)$ — зовите `norm` после каждого вычитания. Произведение двух чисел до $10^{18}$ занимает ~120 бит — `unsigned __int128` (расширение GCC/Clang) спасает; на 32-битных модулях хватает обычного uint64. В `addmod` вместо `%` — одно условное вычитание: сумма меньше $2n$, и это быстрее (при $n < 2^{63}$, чтобы сумма не переполнила uint64).

## Быстрое возведение в степень

Представим показатель в двоичной записи: $a^{13} = a^8 \cdot a^4 \cdot a^1$, потому что $13 = 1101_2$. Квадрируя базу, получаем $a^1, a^2, a^4, a^8, \dots$ — и перемножаем те степени, чьи биты стоят в $e$:

```cpp
u64 powmod(u64 a, u64 e, u64 n) {
    u64 r = 1;
    a %= n;
    while (e) {
        if (e & 1) r = mulmod(r, a, n);   // бит показателя
        a = mulmod(a, a, n);              // квадрируем базу
        e >>= 1;
    }
    return r;
}
```

Инвариант цикла: ответ $= r \cdot a^e$; каждый шаг съедает один бит показателя. 64-битная степень — 64 квадрирования и не больше 64 умножений: **128 операций вместо $10^{19}$**.

```
# 10^6 вызовов powmod, показатель ~ 2^64, модуль p = 10^9 + 7
суммарно:  605 мс    (605 нс на вызов)
# наивный цикл из e умножений: даже по наносекунде — 2^64 нс > 580 лет
```

Тот же трюк работает для любой ассоциативной операции: степень матрицы (Фибоначчи за $O(\log n)$!), композиция перестановок — двоичное разложение показателя ещё всплывёт.

## Алгоритм Евклида

```cpp
long long gcd(long long a, long long b) {
    while (b) { a %= b; std::swap(a, b); }
    return a;
}
// или std::gcd из <numeric> (C++17)
```

**Инвариант:** $\gcd(a, b) = \gcd(b, a \bmod b)$ — общие делители пары не меняются при замене $a$ на $a - qb$, а значит и на остаток. Каждые два шага числа падают минимум вдвое, отсюда $O(\log \min(a, b))$ итераций.

```
# 5·10^5 пар 64-битных чисел
gcd: 28 мс (56 нс на вызов)
# худший случай — соседние числа Фибоначчи: пара ~2·10^18 даёт ровно 88 шагов
```

Худший случай — соседние Фибоначчи (каждое деление даёт частное 1): третья встреча курса с этой последовательностью, и снова в роли эталона. Алгоритму ~2300 лет — «Начала» Евклида, книга VII: старейший алгоритм курса и ни разу не устаревший.

### Расширенный Евклид

Кроме $g = \gcd(a, b)$ находит коэффициенты Безу — $x, y$ с $ax + by = g$:

```cpp
long long extgcd(long long a, long long b, long long& x, long long& y) {
    if (b == 0) { x = 1; y = 0; return a; }
    long long x1, y1;
    long long g = extgcd(b, a % b, x1, y1);
    x = y1;
    y = x1 - (a / b) * y1;
    return g;
}
```

Раскрутка рекурсии пересчитывает коэффициенты нижнего уровня в верхние — обратный ход, как подстановка в системе уравнений. Трассировка $\text{extgcd}(240, 46)$:

| a | b | x | y |
|---|---|---|---|
| 240 | 46 | −9 | 47 |
| 46 | 10 | 2 | −9 |
| 10 | 6 | −1 | 2 |
| 6 | 4 | 1 | −1 |
| 4 | 2 | 0 | 1 |
| 2 | 0 | 1 | 0 |

Проверка: $240 \cdot (-9) + 46 \cdot 47 = -2160 + 2162 = 2 = \gcd$ ✓. Побочный бонус: уравнение $ax + by = c$ разрешимо в целых ⟺ $c$ кратно $\gcd(a, b)$ — коэффициенты Безу дают решение конструктивно.

## Обратный элемент

> [!def] Обратный по модулю
> Обратный к $a$ — такой $x$, что $a \cdot x \equiv 1 \pmod N$; обозначается $a^{-1}$. Существует ⟺ $\gcd(a, N) = 1$: из $ax + Ny = 1$ следует $ax \equiv 1$; а при общем делителе $d > 1$ левая часть $ax$ всегда кратна $d$ и единицей быть не может.

```cpp
// способ 1: расширенный Евклид — работает для любого N
long long inverse(long long a, long long n) {
    long long x, y;
    extgcd(a, n, x, y);                  // ax + ny = 1
    return ((x % n) + n) % n;
}
// способ 2: малая теорема Ферма — только для простого p
//   a^(p-1) ≡ 1 (mod p)  =>  a^(p-2) ≡ a^(-1)
u64 inverse(u64 a, u64 p) { return powmod(a, p - 2, p); }
```

Пример: $3^{-1} \pmod 7 = 5$, ведь $3 \cdot 5 = 15 \equiv 1$. Теперь «поделить на 3» значит «умножить на 5»: $a / b := a \cdot b^{-1}$ — деление по модулю определено, когда $b$ взаимно прост с модулем. Малую теорему Ферма ($a^{p-1} \equiv 1 \pmod p$ для простого $p$ и $a$, не кратного $p$) докажем на занятии про простоту.

```
# 10^6 обратных по модулю p = 10^9 + 7
extgcd:          67 мс     # ×4.3 быстрее
Ферма a^(p-2):  285 мс
# чек-суммы двух способов СОВПАЛИ; a·inverse(a) ≡ 1 — без нарушений
```

Евклид быстрее (в среднем ~19 шагов деления против 45 умножений по `__int128` у Ферма), Ферма — одна строка при готовом powmod, но требует простого модуля и молча выдаёт мусор, если обратного нет. Сверка двух независимых способов — самый дешёвый стресс-тест: разные алгоритмы, один ответ.

**Где обратный работает уже сейчас:** в доказательстве универсальности Картера–Вегмана (занятие 5) шаг «$a \equiv (r-s)(x-y)^{-1}$» — ровно сегодняшний обратный, мы применили его раньше, чем определили. Биномиальные коэффициенты по простому модулю: предпосчитайте факториалы и их обратные — и $C(n,k) = n! \cdot (k!)^{-1} \cdot ((n-k)!)^{-1}$ считается за $O(1)$ на запрос. RSA: секретный ключ $d = e^{-1} \bmod \varphi(N)$ вычисляется расширенным Евклидом — на занятии 13 соберём сегодняшними функциями целиком.

## Задачи практикума

1. **Степень на бумаге.** Вычислите $2^{100} \bmod 1000$ быстрой степенью.

   {{% expand title="Разбор" %}}$100 = 64 + 32 + 4$: шесть квадрирований дают $2^1, 2^2, 2^4, \dots, 2^{64}$ по модулю 1000, затем два умножения: $2^{64} \cdot 2^{32} \cdot 2^4$. Цепочка квадрирований mod 1000: 2, 4, 16, 256, 536, 296, 616, 656; итог $656 \cdot 616 \cdot 16 \bmod 1000 = 376$. Наивно — 99 умножений, быстрой степенью — 9. Степени двойки по модулю 1000 зацикливаются с периодом 100 (после разгона), поэтому «последние три цифры $2^n$» — периодическая функция.{{% /expand %}}

2. **Линейное сравнение.** Решите $5x \equiv 3 \pmod{17}$. Бонус: сколько решений у $6x \equiv 3 \pmod 9$?

   {{% expand title="Разбор" %}}$\gcd(5, 17) = 1$ — обратный существует: extgcd даёт $5 \cdot 7 = 35 \equiv 1 \pmod{17}$, значит $5^{-1} = 7$ и $x \equiv 7 \cdot 3 = 21 \equiv 4$. Проверка: $5 \cdot 4 = 20 \equiv 3$ ✓. Бонус: $\gcd(6, 9) = 3$ делит 3, поэтому решения есть, и их ровно три: сокращаем на 3 до $2x \equiv 1 \pmod 3$, откуда $x \equiv 2 \pmod 3$ — то есть $x \in \{2, 5, 8\}$ по модулю 9. Общее правило: решений либо ноль (если $g \nmid c$), либо ровно $g$ штук.{{% /expand %}}

3. **Сломанное деление.** Коллега пишет `(a / b) % N` и удивляется. Постройте контрпример и почините.

   {{% expand title="Разбор" %}}Целочисленное `a / b` теряет остаток до взятия модуля: $a = 7$, $b = 2$, $N = 5$ — код даст $(7/2) \% 5 = 3$, а честное $7 \cdot 2^{-1} \bmod 5 = 7 \cdot 3 \bmod 5 = 1$ (проверка: $2 \cdot 1 \equiv 2$, и действительно $x = 1$ решает $2x \equiv 7 \equiv 2$). Починка: `mulmod(a % N, inverse(b, N), N)`. Формула коллеги верна лишь когда $b$ делит $a$ нацело — тогда остаток не теряется.{{% /expand %}}
