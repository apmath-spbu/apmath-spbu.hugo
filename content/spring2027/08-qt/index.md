Весь курс наши программы были **конвейерами**: прочитали вход, посчитали, напечатали ответ, вернули ноль из `main` — и процесс умер. Сегодня программа впервые останется жить: окно будет ждать, человек — кликать, программа — отвечать и снова ждать. Это смена парадигмы, а не просто новая библиотека: поток управления больше не принадлежит нам. Инструмент — **Qt 6**, крупнейший GUI-фреймворк для C++. Всё в этом конспекте собрано и снято по-настоящему: каждый скриншот — это `QWidget::grab()` работающей программы, собранной CMake-ом с Qt 6.11 (в скобках у окон нет рамок заголовка — так рендерит offscreen-режим, у вас появится обычная системная рамка).

Примечание к нумерации: в факультетском плане это занятие значится под № 9 — номер 8 там пропущен; наша сквозная нумерация продолжается, дальше номера снова совпадают по смыслу тем.

## Почему именно Qt

- **Родной C++.** Всё, что мы выучили за полтора семестра — классы, RAII, лямбды, шаблоны, — работает напрямую, без прослоек и биндингов.
- **Кроссплатформенность.** Один и тот же код собирается под Windows, macOS, Linux, Android, iOS и встраиваемые системы.
- **Индустриальный стандарт.** На Qt написаны Telegram Desktop, VirtualBox, OBS Studio, среда KDE Plasma, интерфейсы продуктов Autodesk (например, Maya), мультимедийные панели множества автомобилей.
- **Лицензия.** Для нас — открытая LGPL, и вопреки распространённому мифу её хватает даже закрытым коммерческим приложениям, пока Qt линкуется динамически. Коммерческая лицензия нужна в особых случаях: статическая линковка без LGPL-обязательств, приватные правки самого Qt, устройства с «запертой» прошивкой (детали — на qt.io, для курса это не играет роли).

Альтернативы существуют, и о них полезно знать: wxWidgets и GTK (меньше документации и вакансий; GTK — C-стиль), Dear ImGui (прекрасен для игровых инструментов, но там иная модель — интерфейс перерисовывается каждый кадр), Electron (это JavaScript и целый браузер в комплекте; C++ там гость). Qt — самый прямой путь для C++-программиста.

## Первое окно: восемь строк

```cpp
// main.cpp
#include <QApplication>
#include <QPushButton>

int main(int argc, char** argv) {
    QApplication app(argc, argv);
    QPushButton button("Привет, Qt!");
    button.show();
    return app.exec();   // событийный цикл
}
```

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.21)
project(hello LANGUAGES CXX)

find_package(Qt6 REQUIRED COMPONENTS Widgets)
qt_standard_project_setup()

qt_add_executable(hello main.cpp)
target_link_libraries(hello PRIVATE Qt6::Widgets)
```

```sh
cmake -B build && cmake --build build
./build/hello
```

![Окно с кнопкой «Привет, Qt!»](qt-hello.png?width=14em)

Построчно:

- `QApplication app(argc, argv)` — один объект на всю программу: держит связь с оконной системой, очередь событий, настройки. Создаётся **до** любого виджета.
- `QPushButton button(...)` — виджет как обычная локальная переменная. Виджет без родителя — самостоятельное окно.
- `button.show()` — виджеты создаются невидимыми; `show()` ставит окно в очередь на показ. Размер? Виджет сам знает свой удобный размер (`sizeHint`) — по нему окно и раскроется.
- `app.exec()` — здесь программа «останавливается» и начинает жить.

## app.exec(): событийный цикл

`exec()` входит в **событийный цикл** и не возвращается, пока живо хотя бы одно окно. Внутри — знакомая структура данных: **очередь** (семестр 1, занятие 8). Операционная система кладёт в неё события — клик, нажатие клавиши, тик таймера, запрос перерисовки, — а цикл достаёт их по одному и доставляет нужному виджету:

```text
пока (очередь жива):
    событие = очередь.достать()      // клик? клавиша? таймер?
    виджет  = адресат(событие)
    виджет.обработать(событие)       // наш код живёт здесь
```

Следствия, которые стоит понять сразу:

1. **Наш код после `exec()` живёт в обработчиках** — коротких функциях, которые цикл зовёт в ответ на события. Между событиями программа спит и не ест процессор.
2. **Обработчик обязан быть быстрым.** Пока он работает, цикл стоит: окно не перерисовывается, кнопки не нажимаются. Запустите в обработчике сортировку на минуту — окно «зависнет» на минуту. Это ответ на вечный вопрос «почему приложение не отвечает»: кто-то занял событийный цикл.
3. Конвейерные программы не исчезли — они стали **обработчиками** внутри событийных.

## Дерево виджетов и родительское владение

Интерфейс — это **дерево**: окно содержит панели, панели — кнопки и поля. Занятия 1–3 этого семестра внезапно оказались подготовкой к GUI. И у этого дерева есть правило владения:

```cpp
auto* window = new QWidget;
auto* label  = new QLabel("Счёт: 0", window);   // родитель — window
auto* button = new QPushButton("+1", window);   // родитель — window

window->show();
// ...
delete window;   // удалит и label, и button: родитель владеет детьми
```

Родитель в деструкторе обходит детей и удаляет каждого — а те своих детей, и так до листьев. Узнаёте? Это post-order-удаление из занятия 3 — деструктор BST, только встроенный в каждый `QWidget`. Поэтому виджеты создают через `new` и почти никогда не вызывают `delete` вручную: умирает корень — умирает всё поддерево.

Это уже **третья модель владения** в курсе:

| модель | кто удаляет | где встречали |
|---|---|---|
| ручная (`new`/`delete`) | вы | семестр 1, занятие 13 |
| `unique_ptr` | умный указатель | семестр 1, занятие 14; наш BST |
| родительская (Qt) | родительский виджет | сегодня |

Смешивать модели нельзя: завернёте виджет с родителем в `unique_ptr` — получите двойное удаление (родитель удалит, потом умный указатель попробует ещё раз).

## Компоновка: layout вместо координат

Расставлять виджеты по абсолютным координатам (`button->move(40, 60)`) — путь к сломанному интерфейсу: другой размер окна, другой шрифт, другой язык («Сброс» по-немецки — «Zurücksetzen»), HiDPI-экран — и всё разъехалось. Вместо координат Qt предлагает **layout** — объект-правило: «эти виджеты в ряд», «эти — в столбец». Конкретные пиксели layout пересчитывает сам при каждом изменении окна.

```cpp
auto* window = new QWidget;
auto* label  = new QLabel("Счёт: 0");
auto* plus   = new QPushButton("+1");
auto* reset  = new QPushButton("Сброс");

auto* row = new QHBoxLayout;          // кнопки в ряд
row->addWidget(plus);
row->addWidget(reset);

auto* col = new QVBoxLayout(window);  // столбец на окне
col->addWidget(label);
col->addLayout(row);                  // layout вкладывается в layout
window->show();
```

Три рабочие лошадки: `QVBoxLayout` (столбец), `QHBoxLayout` (ряд), `QGridLayout` (таблица — пригодится в домашнем задании для «пятнашек»). Они вкладываются друг в друга на любую глубину — дерево и здесь.

Важная деталь владения: `addWidget` **переподчиняет** виджет — когда layout установлен на окно, добавленные виджеты становятся детьми этого окна. Дерево владения строится за кадром, и `delete window` по-прежнему убирает всё.

## Сигналы и слоты

Как связать «кнопку нажали» с «текст поменялся»? В Qt это называется **сигналы и слоты**:

- **сигнал** — событие, о котором объект сообщает миру: `QPushButton::clicked`, `QLineEdit::textChanged`, `QTimer::timeout`;
- **слот** — реакция: любая функция, метод или лямбда;
- `QObject::connect(отправитель, сигнал, получатель/слот)` — провод между ними.

```cpp
QObject::connect(plus, &QPushButton::clicked, [&count, label] {
    ++count;
    label->setText(QString("Счёт: %1").arg(count));
});
```

Почему это хорошо спроектировано:

- **Типобезопасность.** Мы передаём указатели на методы (`&QPushButton::clicked`), и компилятор сверяет сигнатуры сигнала и слота. Перепутали — ошибка компиляции, а не тихий сбой в рантайме.
- **Многие-ко-многим.** Один сигнал можно подключить к нескольким слотам, один слот — к нескольким сигналам. Интерфейс собирается из связей, как схема из проводов.
- **Лямбды как слоты.** Лямбды из занятия 14 первого семестра — идеальные обработчики: короткие, видят нужные переменные через захват, объявляются прямо у места подключения.

И помните следствие №2 из раздела про событийный цикл: слот работает — цикл стоит. Слоты пишем быстрыми.

## Счётчик кликов: программа целиком

Всё занятие в тридцати строках:

```cpp
// counter.cpp
#include <QApplication>
#include <QWidget>
#include <QLabel>
#include <QPushButton>
#include <QVBoxLayout>
#include <QHBoxLayout>

int main(int argc, char** argv) {
    QApplication app(argc, argv);
    QWidget window;                       // окно — на стеке
    window.setWindowTitle("Счётчик");

    auto* label = new QLabel("Счёт: 0");  // дети — в куче
    auto* plus  = new QPushButton("+1");
    auto* reset = new QPushButton("Сброс");

    auto* row = new QHBoxLayout;
    row->addWidget(plus);  row->addWidget(reset);
    auto* col = new QVBoxLayout(&window);
    col->addWidget(label); col->addLayout(row);

    int count = 0;
    QObject::connect(plus, &QPushButton::clicked,
        [&] { label->setText(QString("Счёт: %1").arg(++count)); });
    QObject::connect(reset, &QPushButton::clicked,
        [&] { count = 0; label->setText("Счёт: 0"); });

    window.show();
    return app.exec();
}
```

![Окно счётчика после трёх кликов](qt-counter.png?width=16em)

Скриншот честный: программа собрана, по кнопке «+1» кликнуто трижды (программно, через `plus->click()` — он испускает тот же сигнал `clicked`), окно снято. Что здесь стоит заметить:

- `window` живёт **на стеке**, дети — в куче под её владением: `main` завершается → деструктор окна забирает всех. Ни одного `delete` в программе нет, и утечек тоже нет.
- Лямбда захватывает `count` **по ссылке**: счётчик живёт в `main` и переживает любое число кликов — замыкание поверх событийного цикла.
- `QString("Счёт: %1").arg(count)` — форматирование по месту; с кириллицей Qt дружит из коробки.

## Ввод пользователя: QLineEdit и валидация

```cpp
auto* input  = new QLineEdit;
auto* result = new QLabel("—");
input->setPlaceholderText("Цельсии");
auto* v = new QDoubleValidator(input);   // не число — не впустит
v->setLocale(QLocale::c());              // точка, не запятая!
input->setValidator(v);

QObject::connect(input, &QLineEdit::textChanged, [input, result] {
    bool ok = false;
    double c = input->text().toDouble(&ok);
    result->setText(ok ? QString("%1 °F").arg(c * 9.0 / 5 + 32)
                       : QString("—"));
});
```

![Конвертер: 36.6 превращается в 97.88 °F](qt-fahrenheit.png?width=15em)

- Сигнал `textChanged` приходит **на каждый символ** — конвертер пересчитывается «вживую», без кнопки «Посчитать».
- **Валидатор** отсекает мусор на входе: буква в этом поле просто не напечатается. Точнее, почти: букву `e` валидатор пропускает — научная запись `1e5` тоже число. И проверка `toDouble(&ok)` всё равно обязательна: пустая строка и одинокий минус валидатор проходят (это «промежуточные» состояния ввода), а числом не являются.
- **Ловушка локали.** `QDoubleValidator` по умолчанию берёт локаль системы: на русской машине он ждёт запятую («36,6») и не пропустит точку. А `QString::toDouble` — наоборот, понимает только точку. Без `setLocale(QLocale::c())` конвертер на русской системе молчал бы вечным «—»: валидатор и парсер говорили бы на разных языках. Общее правило: всякий раз, когда числа приходят от человека, вспоминайте про локаль.
- Знакомый мотив «не доверяй вводу» (семестр 1, занятие 9) в GUI никуда не делся — проверка просто стала интерактивной.

Родственный сигнал `textEdited` приходит только когда текст меняет **человек**, но не при программном `setText`. Разница выстрелит в задаче C практикума.

## Под капотом: MOC

Сигналы и слоты — не стандартный C++. Их обслуживает **MOC** (Meta-Object Compiler) — кодогенератор, который прогоняется над заголовками **до** компилятора и превращает классы с макросом `Q_OBJECT` в обычный C++ (файлы `moc_*.cpp` в папке сборки): таблицы сигналов, метаинформацию, механику доставки. Тот же приём, что препроцессор из занятия 1 первого семестра, только анализирующий структуру классов.

CMake с `qt_standard_project_setup()` запускает MOC автоматически — вы его не замечаете ровно до тех пор, пока не напишете **свой** класс с сигналами и не забудете `Q_OBJECT`. Тогда линкер скажет что-то вроде `undefined reference to vtable for MyWidget` — теперь вы знаете, откуда берётся эта знаменитая ошибка: MOC не сгенерировал свою часть класса.

Правило курса «каждая магия — с разбором до байтов» соблюдено: `connect` работает не волшебством, а сгенерированным кодом, который можно открыть и прочитать. Сегодня мы к тому же обошлись без `Q_OBJECT` вовсе: указатели на методы и лямбды — это обычный C++.

## Задачи практикума

**A. Hello + сборка.** Соберите окно с кнопкой из раздела «восемь строк»: CMakeLists, `cmake -B build`, запуск. Поменяйте текст кнопки и заставьте её закрывать приложение.

{{% notice style="tip" title="Разбор A" expanded="false" %}}
Ничего писать почти не надо — сигнал уже есть, слот уже есть, нужен провод:

```cpp
QObject::connect(&button, &QPushButton::clicked,
                 &app,    &QApplication::quit);
```

Это первый connect «объект-к-объекту» без лямбды: сигнал кнопки напрямую к готовому слоту приложения.
{{% /notice %}}

**B. Счётчик с лимитом.** Доработайте счётчик: после 10 кликов кнопка «+1» выключается (`setEnabled(false)`), а надпись становится красной (`label->setStyleSheet("color: red")`). «Сброс» возвращает всё как было. Подумайте: где хранить лимит и почему лямбда с захватом по значению здесь не сработала бы?

{{% notice style="tip" title="Разбор B" expanded="false" %}}
Состояние (`count`, лимит) живёт в `main`, лямбды захватывают его по ссылке. Захват по значению заморозил бы **копию** счётчика в момент `connect` — кликай не кликай, копия внутри лямбды менялась бы, а сравнение с лимитом в другой лямбде смотрело бы на свою, нетронутую копию. Общее изменяемое состояние — только по ссылке (или в полях класса, как в ДЗ).

```cpp
QObject::connect(plus, &QPushButton::clicked, [&] {
    label->setText(QString("Счёт: %1").arg(++count));
    if (count >= 10) {
        plus->setEnabled(false);
        label->setStyleSheet("color: red");
    }
});
QObject::connect(reset, &QPushButton::clicked, [&] {
    count = 0;
    label->setText("Счёт: 0");
    plus->setEnabled(true);
    label->setStyleSheet("");
});
```
{{% /notice %}}

**C. Конвертер туда-обратно.** Два `QLineEdit`: Цельсии и Фаренгейты, правка любого поля пересчитывает второе. Осторожно: наивная связка зациклится — `setText` во втором поле испустит его `textChanged`, тот пересчитает первое поле, и по кругу. Как разорвать кольцо?

{{% notice style="tip" title="Разбор C" expanded="false" %}}
Подключаться к `textEdited` вместо `textChanged`: он испускается только при правке **человеком**, а программный `setText` его не трогает — кольцо разомкнуто самой семантикой сигнала. (Альтернативы — флаг «сейчас обновляю» или `blockSignals` — работают, но это ручной труд там, где Qt уже подумал за нас.)
{{% /notice %}}

## Домашнее задание: «Угадай число» (сдача через Git)

1. **Игра.** Программа загадывает число от 1 до 1000; поле ввода с валидатором, кнопка «Проверить», подсказки «больше/меньше» в `QLabel`, счётчик попыток. Да, это двоичный поиск (семестр 1, занятие 12) — руками пользователя: за 10 попыток число находится всегда.
2. **Интерфейс на layout-ах.** Окно переживает любой ресайз; после победы — поздравление и кнопка «Новая игра».
3. **Санитарный минимум архитектуры.** Логика игры — отдельный класс без единого включения Qt, проверяемый юнит-тестом из консоли; интерфейс — тонкая обёртка над ним. Это разделение — половина оценки: привыкайте, что «мозг» программы не знает про кнопки.
4. **★ Таймер.** `QTimer` показывает секунды с начала партии; по победе останавливается.
5. **★★ «Пятнашки».** `QGridLayout` 4×4 из кнопок, ход по клику, проверка победы. Перемешивайте **случайными ходами** из собранного поля, а не случайной раскладкой плиток: ровно половина всех раскладок нерешаема (инвариант чётности перестановки), и наивный shuffle подарит игроку несобираемую головоломку через раз.
